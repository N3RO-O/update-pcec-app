01

One member app. A shared office workspace.

PCEC Connect brings announcements, events, community activity and member account details into one place. Administrators use the same app with additional office screens.

Phase 1 · Prepared in the app

For members

Home, Events, About, Donate and Profile form the main navigation. Members can register for events, share community posts, react and comment, report content, update their profile and send a message to the office.

The app is a PWA: a website that can also be added to a phone’s home screen. It has one set of member screens for phone and desktop.

Office access

For the PCEC administrator

Manage members and suspensions, publish announcements, events and NDC posts, maintain donation instructions, review Contact Us messages and moderate community content.

Administrator screens help guide the operator. The server must also check permission for each protected action; hiding a screen is not sufficient protection.

Outside this version: automated payment collection and donation receipts, QR attendance, certificates, push notifications and an AI member assistant. The Android store wrapper is prepared but has not been proved installed on a real phone. These are separate future decisions.
02

The system picture

The browser displays the app. Supabase provides the account, records and file services. The intended hosting plan serves the app’s website files separately from that backend.

Proposed additional layer: Cloudflare. It can screen traffic and deliver public website files nearer to members. The domain and hosting setup still need verification. Direct Supabase account and database requests keep their own permissions and request limits. See the benefits, limits and estimated cost.

What opens without internet?

The service worker saves the app shell: screen code, styles and icons. It does not cache Supabase member records for offline use. Sign-in, fresh records and saving changes need a connection.

Offline opening is not offline access to every feature. The app prompts when a new version is ready.

What protects API usage?

The prepared client combines duplicate reads, limits concurrent requests, times out slow calls and pauses after repeated failures. Writes are not automatically retried.

A bot can bypass browser limits. Live server limits, upload quotas, alerts and an agreed spending budget remain necessary. See the cost review.

Three important journeys

Sign-up and password recovery

  1. The member submits details or asks to reset a password.
  2. Supabase Auth handles the request; account emails direct the member back to the approved app address.
  3. After the required account checks, the app reads the profile and decides which screen to show.

Email confirmation was off in the 5 October live review. Branded templates are prepared; the official sender, delivery and link destinations must be tested. Email confirmation does not replace administrator second-step login.

Read a post or register for an event

  1. The app makes a request using the member’s session.
  2. The database checks the relevant account, ownership and access rules.
  3. The app shows the allowed result or a helpful error. Large lists should load in manageable pages.

Database access rules are often called RLS: row-level security. Prepared changes have local tests; live acceptance is still required. Member Management uses prepared 25-person paging and search.

Upload a photo · Prepared path

  1. The app crops or compresses the image and submits it to the checked-upload function.
  2. The server checks the session, permission, allowed file content and quota before placing the file in Storage.
  3. A database record points to the file. Private images use short-lived viewing links.

This client depends on the new upload function and matching rules. They were not live in the last review, so uploading is not ready for production acceptance. Profile-photo links were public; their audience still needs a decision.

03

Member and administrator guide

Open a topic for the main steps. Use sample accounts in an isolated test version for practice; the local app currently connects to the existing backend.

Start an account, sign in or recover access

Choose Sign Up from the login page, enter your own details and review the consent text. Once email verification is enabled, follow the confirmation message before accessing member content.

To recover access, choose Forgot your password, enter your email and follow the reset message. Never forward account links or verification codes. Closing or refreshing this version can require another sign-in because credentials are held in memory.

Live email delivery and administrator second-step login are still pending. A successful local screen is not proof that a real recovery message arrives.

Read news, join an event and find office information
  • Home: read announcements, open the Community Feed and check the notification bell.
  • Events: open an event for its date, place and registration action. Review your registration before submitting.
  • About: view PCEC information and office details.
  • Profile → Contact Us: send the office a message. This is an office inbox, not an instant chat or emergency service.
Update a profile and take part in the community
  • Profile: edit permitted personal details and crop a profile photo. Membership and NDC information are available from the account area.
  • Community: post, react or comment. Report inappropriate material and block a member when needed; administrators can moderate posts.
  • Media: follow the current upload screen’s supported image types. Checked uploads require the server rollout described above.
  • Settings/account: review the available account actions, including deletion. Deletion needs the server service and a deliberate confirmation.

Notification read status is per device. Phone numbers are checked for format, not verified by an SMS call. Profile photos require an approved viewing policy.

Use Donate and understand what it records

Open Donate to review the office’s approved GCash, Maya or bank instructions and QR images. Complete the transfer in the payment provider’s own app.

This version does not automatically collect a payment, confirm that money arrived or issue a donation receipt. Confirm acknowledgements with the office through its approved process.

The income plan contains proposals, not approved fees or an active payment gateway.

Administrator: manage members and office content
  • Members: search, move through 25-person pages, mark a member reviewed or suspend an account according to PCEC policy. New/Official Member badges do not prove dues were paid.
  • Announcements, Events and NDC: maintain accurate content and crop supported images before publishing.
  • Donation Methods and About: verify payment instructions, office details and public links before changing them.
  • Inbox and Community: review office messages and reported posts; handle member information through approved private channels.

Do not give someone administrator access only to help them use the app. Named operators, second-step login, server permissions and an access-revocation check are launch requirements.

05

Run it, check it, then release it.

A working local preview is useful evidence. It still needs the right hosting, backend settings and people to support a public release.

Available locally

Preview and verify

The Windows starter or development command builds the app and opens a local website. Screen tests use a fake backend; database-rule tests run in an isolated local database.

Local browsing uses the existing backend unless configured otherwise. Do not treat it as a separate sandbox. Real Android, iPhone and member-pilot evidence remain pending.

Live setup pending

Coordinate the release

Approve the member address, create an isolated test setup, install matching database rules and server functions, configure email delivery and administrator protection, then test the essential member journeys.

The prepared release script checks source and website files. It cannot by itself prove email, permissions, uploads or recovery. Publishing the Scorecard does not deploy the member app.

Draft for approval

Keep the service running

Name the support owner and deputy. Agree a monthly budget and alert destination. Arrange restricted backups of records and files, rehearse a restore and test a rollback.

For an outage, suspected exposure or abnormal spending: record the incident privately, escalate to the maintainer and leadership, involve the privacy officer when needed, and prove recovery before reopening.

Who owns the next decisions?

  • PCEC administrator · draft owner: account support, content operations and coordination. The named person, deputy and official email are still pending.
  • Technical maintainer: controlled releases, server permissions, alerts, recovery and technical evidence. A named responder and access arrangement are needed.
  • PCEC leadership and appointed privacy/legal advisers: approve spending, privacy wording, retention, support responsibilities and the launch decision.

No paid service, monitoring recipient or recovery guarantee is approved by this guide.
