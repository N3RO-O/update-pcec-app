## Test environments and method

Browser tests use Playwright with intercepted Supabase requests and in-memory fixtures. Database policy/RPC tests rebuild source SQL in isolated PGlite; this is not a production restore. The reconstructed catalog contains 38 application tables, one view and 29 migration files. Local request guards remain enabled. Focused tests cover current interaction and failure states; browser emulation does not replace physical-device acceptance. Screenshots use explicitly described sample data.

The original audit ran 50 suites, with 41 passes. Latest available outcomes across the same suite names are 49 passed and 1 not passed/environment limited. The table records each latest completed result; partial in-progress runs never overwrite a completed result. New media, documentation and portfolio checks are recorded separately. A failed whole-suite result is not called passed because earlier scenarios within it succeeded.

## Findings and changes to the older journey harness

The original journey expected removed bottom-bar links, older About wording, an obsolete photo-fit button, old feed controls and a service-worker refresh-bar contract. It now follows the actual visible Menu, reference login layout, inline comment controls and current progress bar. The dedicated passing app-updates suite supplies release activation/draft preservation coverage in place of the obsolete worker mutation block. Relative fixture dates replace stale fixed dates. QR comparisons await image decoding and cropper readiness.

HTTP requests and Realtime sockets are isolated in the broad journey. Real permission, ledger and private-file assertions remain. Very fast multi-action stories can reach the real per-document request guard; separate stages reload a fresh document rather than disabling the guard. Diagnostic logs stay in ignored local test output. Check the whole-suite results above for any remaining browser journey failure; focused passes do not erase them. Firefox launch returned spawn UNKNOWN in this Windows environment and is not a verified browser.

## External acceptance and exclusions

Still required: real confirmation and recovery email completion; administrator MFA enrollment, recovery and server enforcement; isolated restore of database plus Storage; final domain/Auth callback acceptance; a current Android/iPhone pilot; and a controlled donation reconciled against the bank/provider record. Background push, durable offline writes and the optional bilingual assistant are not shipped. AdSense remains disabled; Google approval is external.
