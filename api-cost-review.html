Why consider Cloudflare for PCEC?

Cloudflare can sit between members and the website, helping screen harmful traffic and delivering website files from servers closer to the visitor. For PCEC, that could mean quicker access for members in the Philippines and abroad, with less traffic reaching the website host.

Proposed layer · setup and protection are not verified for the member app. Benefits depend on the chosen hosting, domain settings and plan.

01 · Security

Help filter harmful traffic.

DDoS protection helps resist floods of attack requests. A web application firewall, or WAF, screens known malicious patterns. Free includes a limited managed ruleset; broader rules and bot controls depend on the plan and settings.

This supports the app’s own safeguards; it does not guarantee that every bot or database attack is blocked. WAF coverage · DDoS protection.

02 · Speed

Bring website files closer.

Copies of eligible images, styles, fonts and scripts can be served near the member. This can shorten loading times and reduce repeated downloads from the website host.

Cache public website files only. Member records and private account responses must stay outside shared caching. How caching works.

03 · Reliability

A limited fallback for public pages.

The optional Always Online feature may show saved public pages when the website server is unreachable. It does not keep sign-in, password resets, member records or form submissions working during a service outage.

It is not a backup or recovery plan for PCEC’s database or photos. Always Online scope · Limitations.

04 · Visibility

See traffic and unusual activity.

Traffic, cache and security views help the maintainer spot changes in requests and blocked activity. The detail and history available depend on the plan.

These views do not show every direct Supabase request or replace spending alerts sent to PCEC’s chosen administrator. Available analytics.

Where its protection stops. Cloudflare protects traffic actually routed through its network. The prepared app calls Supabase directly for accounts, records and uploads. Putting the website behind Cloudflare alone would not bring those requests behind PCEC’s Cloudflare rules. How traffic routing works.

PCEC still needs safe database queries against SQL injection, server permissions, upload checks, request limits and spending controls. Cloudflare is an additional layer, not a guaranteed maximum API bill.

What the review found

Verified live
  • Login rate limits are present.They slow repeated sign-ins and token requests from the same internet address.
  • Bot protection needs setup.CAPTCHA and email confirmation are off. Leaked-password protection is also disabled; that feature requires a paid plan.
  • The upload gate is not deployed.Only the older account-deletion function is currently listed. New protections must be released together with the app and database changes.
  • Monitoring needs care.Broad log searches are nearing their allowance. Use focused checks so monitoring does not generate unnecessary usage.
Prepared locally
  • Fewer repeated requests.Matching reads share a request. Background feed checks pause when hidden or offline and have a fixed stopping point.
  • Failures have a stopping point.No automatic retries of writes. Deadlines, capped session-renewal attempts and pauses after repeated failures prevent runaway work.
  • Uploads have a shared allowance.New uploads are photos only, up to 5 MiB. Member and project limits stop one account or many accounts from filling storage without review.
  • Administrators get usage warnings.Heavy server activity, blocked repeat requests and shared upload allowances reaching 80% create private dashboard warnings after rollout. Email alerts await a chosen recipient.

Before spending increases

  1. Choose a monthly budget and an administrator email address for alerts.
  2. Keep Free until a paid service is approved. If upgrading, keep the spend cap enabled and approve each additional project or paid feature.
  3. Set limits separately with the email and hosting providers. Supabase's cap covers selected usage; it is not a universal dollar ceiling.
  4. Release and verify the new server, database and app safeguards together. Configure CAPTCHA, email delivery and confirmation.
  5. Review usage after the member pilot. Raise allowances only when the budget supports them.

Browser limits alone cannot stop bots. Public photo downloads and denied API requests can still use resources. Provider limits, server permissions and gateway controls must work together. Email notifications are not active yet.
